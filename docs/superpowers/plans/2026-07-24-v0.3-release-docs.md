# v0.3 Documentation and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Document the actual v0.3 interaction/runtime flow, align product versions, and make a verified `v0.3.0` tag produce a GitHub Release.

**Architecture:** Keep root READMEs task-oriented, move subsystem detail to focused guides, define one repository release version, verify all version surfaces in Python, and let a tag-only workflow publish release notes from the changelog.

**Tech Stack:** Markdown, Python 3.13 stdlib, pytest, GitHub Actions, gh CLI

## Global Constraints

- Documentation must not claim proof of phenomenal consciousness.
- Issue #102 must be independently traceable and closed by the release PR.
- Product version is `0.3.0`; release tag is `v0.3.0`.
- A workflow may publish an existing tag but may never create a tag.
- Tagging occurs only after the release PR is merged and all release gates pass.
