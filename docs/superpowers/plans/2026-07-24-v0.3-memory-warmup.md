# v0.3 Windows Memory Warmup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent the first memory write from deadlocking under MCP stdio on Windows by loading the embedding stack on the main thread before async worker threads are used.

**Architecture:** Add public, idempotent warmup boundaries to `E5EmbeddingFunction` and `MemoryStore`. Invoke the store boundary synchronously during MCP startup before the first `await`, preserving asynchronous encoding after startup.

**Tech Stack:** Python 3.13, pytest, unittest.mock, sentence-transformers, MCP stdio

## Global Constraints

- The fix must close issue #99 without changing the embedding model or persisted vector format.
- Model loading must occur on the main thread before MCP stdio serving creates worker threads.
- Existing direct `MemoryStore` users and lazy encoding behavior remain compatible.
- Tests may not download a model or require Windows hardware.

```python
def _sentence_transformer_class() -> type:
    try:
        from sentence_transformers import SentenceTransformer
    except ImportError as error:
        raise ImportError(
            "sentence-transformers is required; run the repository setup command"
        ) from error
    return SentenceTransformer


def warmup(self) -> None:
    if self._model is None:
        transformer = _sentence_transformer_class()
        self._model = transformer(self._model_name)
        logger.info("E5EmbeddingFunction: loaded model %s", self._model_name)
```
